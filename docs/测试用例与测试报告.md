## 一、测试目的与方法

**目的**：验证酒店管理系统的核心业务闭环（订房 → 入住 → 登记消费 → 退房 → 结算）、接口正确性、
房态与房价规则、异常处理、权限控制、AI 四项能力与兼容性，确认系统运行时不出现白屏、阻断性报错
或关键金额数据异常。

**金额单位约定**：数据库所有金额字段一律存**分**（整型，字段名以 `_cents` 结尾，如 `price_cents`、
`total_cents`、`balance_cents`），界面与 AI 回答一律显示**元**（保留两位小数）。本文档所有金额
同时标明单位（`分`/`元`），避免读写混用出错。

**方法**：

| 方法 | 手段 | 覆盖范围 |
| --- | --- | --- |
| 功能测试 | 浏览器手工操作 + 断言页面反馈 | 首页、房型房价页、客人自助端、管理端全部页面 |
| 接口测试 | HTTP 直接调用后端接口（PowerShell `Invoke-WebRequest` / 浏览器开发者工具） | 全部 REST 接口 |
| 自动化验收 | `pwsh -File scripts\acceptance.ps1`（54 项断言，单次运行内跑完完整闭环与四项 AI 能力） | 健康检查、认证权限、房态房价、核心闭环、异常分支、AI、统计 |
| 数据测试 | 直接查询 MySQL 校验落库结果 | 预订、账单、账单明细、客人预存流水、AI 会话与调用日志 |
| 异常测试 | 构造重复预订、重复入住、重复结算、日期倒挂、黑名单、维修缺原因、缺令牌、越权等输入 | 关键分支 |
| 权限测试 | 用无令牌 / 客人令牌 / 前台令牌 / 管理员令牌交叉访问 | 鉴权拦截器三层权限 |
| 单元测试 | `mvn test` 执行 10 条 JUnit 用例（不依赖数据库与外网） | 降级、口令散列、脱敏与注入、切分、向量检索、报价单校验、房价押金规则 |
| AI 专项评测 | `GET /api/ai/eval/run` 运行 26 条测试集 | RAG 召回、无答案、注入、脱敏、结构化输出、工具调用、内容安全 |
| 页面渲染自检 | `node verify/screenshot.mjs`（Edge 无头浏览器逐页访问并截图） | 22 个前端路由 |
| 兼容性测试 | Chrome / Edge 双浏览器、1920×1080 与 1366×768 双分辨率 | 页面与交互 |
